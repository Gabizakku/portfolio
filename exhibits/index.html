Reference first: pairing credits to the right invoice

The rule: two documents are the same thing only if a stable reference says so. Amount is a

consequence, never evidence.


def pair_credit_notes(open_items, credit_notes):
    # 1. exact reference match only
    by_ref = {i["invoice_ref"]: i for i in open_items if i.get("invoice_ref")}
    paired, orphans = [], []
    for note in credit_notes:
        target = by_ref.get(note["against_ref"])
        if target is None:
            orphans.append(note)          # goes to a human, not to a guess
            continue
        paired.append((target, note))
    # 2. amount is a *check*, not a matcher
    mismatched = [(t, n) for t, n in paired
                  if abs(t["open_amount"] + n["amount"]) > 0.01]
    return paired, orphans, mismatched

Why it matters: an amount-first match has a plausible failure mode — same amount, wrong

invoice — and the resulting statement is internally consistent and wrong. Reference-first

converts that silent error into an orphan row a person can see.

Driving a Java desktop app through its accessibility tree

Shape of the bridge (Java Access Bridge, called through ctypes). One long-lived client;

attach once per process, not once per action.


jab.initialize()                       # once
vm_id = next(iter(jab.enumerate_jvms()))   # the running client, not a new one
root = jab.get_accessibility_info(vm_id)

def find(role, name, node=root):
    for child in jab.children(node):            # depth-first over the AX tree
        if jab.role(child) == role and jab.name(child) == name:
            return child
        hit = find(role, name, child)
        if hit: return hit

field = find("text", "Reference")
jab.set_text(field, value)
assert jab.text(find("text", "Reference")) == value   # re-read, always

Two rules that keep this stable: never address a component by screen position, and always

re-read the field after writing it. The accessibility tree survives window moves, theme

changes and a user working in the same app; coordinates do not.

Read-back verification: making done mean done

Every artefact-producing step returns evidence, not a boolean.


@dataclass
class Artefact:
    path: str
    sha256: str
    rows: int
    total: Decimal
    read_back: dict

def emit_statement(build, expected_total):
    path = write_workbook(build)
    back = read_workbook(path)                       # re-open, don't trust the writer
    a = Artefact(path, sha256(path), len(back.rows), back.total,
                 {"rows": len(back.rows), "total": str(back.total)})
    assert a.total == expected_total, f"subtotal drift on {path}"
    return a

Two habits in ten lines: the writer is never the reader, and the total is checked against the

source export rather than against the writer's own arithmetic.
